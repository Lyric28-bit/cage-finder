## What it is
Installable offline PWA for a warehouse sorter: type a suburb from a parcel sticker, get the cage. Plain HTML/CSS/JS, no build step, no backend. Called "Cage Notes"; the repo and URL keep the old name "cage-finder".

## Screens and features
- **Main screen**, styled like a plain notes app: "Notes" header, `⋯` menu (Map / Export / Import / Reset to sheet data), "Search notes" box.
- **The note** (js/manage.js, renders into `#manage-root`), shown while the search is empty: one line per cage (colour dot, name, count, suburb preview) plus a collapsible Local line. Cartons lines show the map postcode range + EST before the count.
- **Edit lock**: the note is locked by default. Tapping a cage line shows its suburbs (with postcodes), View photo and, on Cartons cages, "Map postcodes <range>". **Edit** (right of "Cages", reads **Done** while editing) unlocks rename, colour, add/remove suburbs, per-suburb postcode boxes, delete, photo buttons, + New cage and Local → Move. The note re-locks whenever it's rebuilt. "Move to cage" on a LOCAL result and "Add to a cage" on no match stay available (dialog with Save).
- **Search** (`renderSuggestions` in app.js): typing swaps the note for a filtered copy in `#note-results`: same cage lines, matching suburbs under their cage (or Local) with the typed letters in `<mark>`, best cage first, top 30. A suburb on two cages shows under both. Enter opens the first `.suggestion`. Typo and Pt/Mt matches show without a highlight. Each row shows that cage's own postcode (`postcodesAt`); Cartons cages show "est." beside the name and EST after the postcode. Cage photo thumbnails stay on the lines and open the viewer.
- **Postcode search**: 3-4 digits lists places whose postcode starts with them, only under the cages whose own postcode matches.
- **Result**: cage name in a thick block of its colour; "Postcode NNNN" under the suburb (per band); "on 2 lists" bar for multi-cage suburbs; yellow "You typed X, showing Y" bar when the search text isn't in the chosen name (not for prefix typing or postcode search); "Estimated from the region map, check the map" on estimated cages; sheet photo thumbnail + "Click to zoom"; on Cartons cages "Cage postcodes <range> EST".
- **Check picture**: when the cage has a sheet photo, the main button reads "Check picture" (opens the viewer) and becomes Done once the viewer closes (✕ swaps it directly; the dialog close event covers Esc/Back, Chrome fires it ~0.5s late). Two-cage suburbs open the first cage's photo. No photo = Done straight away.
- **Map postcodes box** (`openEstimate`, `#dlg-est`): tap EST on a result, or "Map postcodes" in an opened Cartons panel. Shows compact runs (`compactCodes`) and each postcode with its suburbs: grey = not on this cage on this device, * = on the map's line. EST is a plain span (not tappable) inside other buttons (search rows, note lines) to avoid nested buttons.
- **Look-alike warning** (`similarPlaces` in js/match.js): the result lists names 1 letter off (2 when both are 6+ letters) that go to a different cage, e.g. Enfield LOCAL vs Penfield North Cartons. Worked out live. Same-destination pairs and short names skipped on purpose. Each is a button opening its own result.
- **Approved by**: adding or moving a suburb into a cage where it isn't on the sheets needs a name (add/move dialog `add-approver`, Edit-mode add line; never pre-filled). Stored in `data.approvals` (`suburb|cage` -> { by, at: YYYY-MM-DD }), moved on rename, removed with the suburb/cage and by applyUnsure, filtered in replaceData, exported. "On the sheets" = data/cages.json minus unsure.json (`ref.sheet`, `onSheet` in app.js). A renamed cage keeps `cage.sheetName` (its first name; no other cage may take it); `linkSheetNames` (in migrate) links cages renamed before this existed to the unclaimed sheet cage sharing over half their suburbs. Result and note show "Not on the sheets · approved by X, date", or amber "no approval noted" for older adds. Edit mode refuses clearing an off-sheet approver. If cages.json fails to load nothing is flagged (deliberate).
- **Sheet photos** (js/photos.js): one photo per cage, **on the device only** in IndexedDB (`cage-notes-photos`, key = normalised cage name), shrunk to 2000px JPEG. 📷 on each cage line in Edit mode; panel has View / Change / Remove. Rename moves the photo, delete removes it. Export/Import doesn't carry photos. Startup never waits on IndexedDB (some iOS versions stall).
- **Street map** (js/map.js, `#dlg-map`): Leaflet 1.9.4 (vendored in lib/leaflet, loaded on first open) + OpenStreetMap tiles, full-screen dialog. Opens from `⋯ → Map` (whole city), **Show on map** in an opened Cartons panel (between View photo and Map postcodes; fits the cage's loop) and on Cartons result bands (pins the suburb, falls back to the cage). `app.openMap({ suburb, cage })`. Search box: prefix, word-start, contains, then editDistance <= 2 over data/suburb-points.json; pick = pin (circleMarker, no marker images shipped) at zoom 14. **Cage lines** control (every view): off = only the opened cage's dashed loop, on = all 6 in cage colours + key with ±km (`within`); the – / Key button folds the key away and keeps the lines; state kept while the app is open. Lines are matched by cage name and use the live cage colour; a renamed or new cage has no line. Close has autofocus so the phone keyboard stays down. Not done (review nice-to-haves): Back on Firefox Android may jump to search, no offline message for grey tiles, tile eviction is oldest-first.

## Data
- Each device keeps its own copy in localStorage; edits don't sync. Export/Import in `⋯` moves them. A sheetVersion bump only reaches a device via ⋯ → Reset to sheet data, which wipes on-device edits (Export first).
- **data/cages.json** (`sheetVersion` at the top): 19 sheet cages, 407 suburbs transcribed from the sheet photos (verified 2026-10-22, don't re-verify), plus 6 Cartons cages (City, North, North East, Port, Regency, South; 271 suburbs) estimated from the region-map photos, unverified.
- **data/adelaide-suburbs.json**: 158 Adelaide metro suburbs (SA Gov list, 5000-5199, minus ones on a sheet). These show as LOCAL. Happy Valley is in both on purpose (Mildura's is a different place).
- **data/postcodes.json** (shipped reference, no reset needed): 643 sheet names matching exactly one locality in the SA Gov suburbs data (data.sa.gov.au, CC-BY 4.0, 2022-03-17), cross-checked against two more datasets (see HISTORY.md). Lyric's rule: **only add a postcode when 100% sure.** Left out on purpose: every Mildura-sheet name (interstate), Hamilton on Mount Gambier (Hamilton VIC), the 55 names with no SA match, and 9 doubtful ones Lyric is checking at work. Lyric fills gaps in-app.
- **Postcode precedence** (`postcodesAt` in app.js), per result band: a postcode typed in-app wins (`data.postcodes["suburbKey|cageKey"]` or `"suburbKey|local"`; '' means none; moved on cage rename, removed with the suburb or cage, imports keep only valid entries); else LOCAL bands use the Local list's postcode and cage bands use data/postcodes.json. Per band because Happy Valley LOCAL (5159) and Happy Valley on the Mildura sheet are different places.
- **data/unsure.json** (shipped, no reset): Cartons suburbs not 100% sure, per cage, with a `version`. `applyUnsure` (js/store.js) moves each one still on that cage to Local (shipped postcode if exactly one; a typed "suburb|cage" postcode moves to "suburb|local") and sets `data.unsureApplied`. Runs on start and after Import/Reset; replaceData copies `unsureApplied`, so old exports get the move and new exports keep Lyric's moves. To un-hide one for everyone: delete it from the list and bump `version` (only removals are safe; a bump re-applies the whole list). Lyric moves them back in-app as he checks them. Currently 77 sure, 194 unsure; Regency has 0 suburbs.
- **data/estimated.json** (shipped, no reset): `cages` = the estimated cages (remove one once Lyric verifies it). `areas` = per Cartons cage, every postcode inside its region map's drawn loop with suburbs `{ name, edge? }`; the ranges on the note, result and panel come from here (`mapArea`/`postcodeRange` in app.js), not the live suburbs. Ranges: City 5000-5082, North 5106-5121, North East 5070-5098, Port 5011-5023, Regency 5010-5094, South 5160-5173. Edit the JSON by hand to change one; the scan scripts aren't in the repo. A Cartons cage renamed in-app loses its EST and map range (both keyed by name).
- **data/suburb-points.json** (shipped): `[name, postcode, lat, lng]` for 465 metro suburbs (SA Gov Suburbs_geojson, CC BY 3.0 AU, postcodes 5000-5199): centroid of the largest part, moved inside when it fell outside (Woodville, Hewett). Every Cartons and Local name has a point (tests.html checks).
- **data/region-loops.json** (shipped): the 6 traced Cartons loops as lat/lng, from the photo pixels via an affine fit to the suburb labels printed on each photo. `within` = worst label miss rounded up (km). Regency (v23) was refitted to 7 road intersections read off OSM tiles, using a second full photo (ShareX 2026-10-27_22-48-53): fit 0.08 km, leave-one-out worst 0.18 km, shown as ±0.3. Derived from work photos, Lyric OK'd it public 2026-10-27. Traced pixel data (maps.json) is in an old session scratchpad, not the repo.
- **Renamed default cages**: `CAGE_RENAMES` in js/store.js, applied once per device by `applyRenames` (`data.renamesApplied`, copied by replaceData) via `app.migrate()` on start and after Import/Reset; only renames a cage still called the old name. The photo follows via `movePhotosOfRenamedCages` (app.js), retried each start. To rename another default: change data/cages.json (no sheetVersion bump), add a CAGE_RENAMES entry with the next id, and update tests.html and the RENAMED map in tests-ui.html.
- **Lyric's placement rules**: suburbs on the printed sheets stay on their sheet cage even where a region map overlaps (e.g. Aldinga/Seaford/Willunga stay Victor Harbor); he moves things himself in-app. Suburbs still LOCAL weren't inside any region map.
- **Open questions** (Lyric asking his boss): Pinkerton Plains (Barossa and Kadina sheets); Aldinga/Seaford/McLaren Vale/Willunga (Victor Harbor sheet, but the South Cartons sign has SEAFORD crossed out with ALDINGA written in, and the South map covers them); Payneham (on the City/North East map line); a "WINGFIELD CARTONS" sign under the Regency map (Wingfield is on unsure.json until he confirms).

## Rules and quirks
- **Update this file with every push**, folded into the commit(s) being pushed. Add the version to HISTORY.md too.
- **Never commit or push sheets/** (workplace photos) or any photo. The site is public. sheets/ is gitignored and stripped from main's history. Local branch `backup-with-photos` still has them: never push it, never push --all. Check `git ls-files sheets` is empty before pushing.
- Pushing: Claude can run `git push origin main` (credentials cached) but only after Lyric says yes for that push. If it asks for a login, Lyric runs it himself in a normal PowerShell window.
- Deploying: bump VERSION in sw.js (and add any new file to its FILES list). If cage data changes, also bump sheetVersion in data/cages.json. Installed apps show "New version ready. Tap to update." Pages usually goes live within a minute. Map tiles are cached as viewed in a separate `cage-tiles` cache (cap 3000, oldest 500 dropped; not `cage-finder-*`, so activate keeps it). OSM's tile policy forbids bulk prefetching, so don't add pre-downloading.
- Saved versions (tags are local only, each with a Desktop folder copy): `v1-original` (pre-redesign; folder `Shipping-App-backup-2026-10-24`), `v2-cage-notes`, `v3-photos`, `v4-view-photo` (v8, old suggestion-list search), `v5-note-search` (v10), `v6-tap-similar` (v11), `v7-failsafes` (v12), `v8-before-est` (v20; folder `Shipping-App-v8-before-est-2026-10-27`), `v9-before-map` (v21; folder `Shipping-App-v9-before-map-2026-10-27`). The other folders are named `Shipping-App-<tag>-2026-10-24`.
- Lyric shares screenshots via ShareX: read the newest file in C:\Users\Lyric\Documents\ShareX\Screenshots\<yyyy-mm>.
- Camera/OCR scanning was built and removed at Lyric's request; don't re-add unless asked (sheet photos are a different, manual feature). A password lock was dropped: it can't protect a public static site.
- The file tools turn typed backslash-u escapes into real characters. For a literal `\u0300`-style escape, build the backslash with `[char]92` in PowerShell.
- No Python or Node on this PC. Use PowerShell (Add-Type C# for anything heavy); Git Bash has perl and sed.
- Claude Code auto mode blocks `powershell -ExecutionPolicy Bypass -File` for check.ps1 and scratch scripts (serve.ps1 in the background was allowed). Run the check's steps by hand (git + ConvertFrom-Json) or ask Lyric to run it. serve.ps1 now has an exact allow rule in .claude/settings.local.json (git-excluded), added 2026-10-27 at Lyric's OK.

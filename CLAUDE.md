## What it is
Installable offline PWA for a warehouse sorter: type a suburb from a parcel sticker, get the cage. Plain HTML/CSS/JS, no build step, no backend. Called "Cage Notes"; the repo and URL keep the old name "cage-finder".

## Screens and features
- **Main screen**, styled like a plain notes app: "Notes" header, `⋯` menu (Map / Export / Import / Reset to sheet data), "Search notes" box.
- **The note** (js/manage.js, renders into `#manage-root`), shown while the search is empty: one line per cage (colour dot, name, count, suburb preview) plus a collapsible Local line. Cartons lines show the map postcode range + EST before the count.
- **Edit lock**: the note is locked by default. Tapping a cage line shows its suburbs (with postcodes), View photo and, on Cartons cages, "Map postcodes <range>". **Edit** (right of "Cages", reads **Done** while editing) unlocks rename, colour, add/remove suburbs, per-suburb postcode boxes, delete, photo buttons, + New cage and Local → Move. The note re-locks whenever it's rebuilt. "Move to cage" on a LOCAL result and "Add to a cage" on no match stay available (dialog with Save).
- **Search** (`renderSuggestions` in app.js): typing swaps the note for a filtered copy in `#note-results`: same cage lines, matching suburbs under their cage (or Local) with the typed letters in `<mark>`, best cage first, top 30. A suburb on two cages shows under both. Enter opens the first `.suggestion`. Typo and Pt/Mt matches show without a highlight. Each row shows that cage's own postcode (`postcodesAt`); Cartons cages show "est." beside the name and EST after the postcode. Cage photo thumbnails stay on the lines and open the viewer.
- **Postcode search**: 3-4 digits lists places whose postcode starts with them, only under the cages whose own postcode matches.
- **Result**: cage name in a thick block of its colour; "Postcode NNNN" under the suburb (per band); "on 2 lists" bar for multi-cage suburbs; yellow "You typed X, showing Y" bar when the search text isn't in the chosen name (not for prefix typing or postcode search); "Estimated from the region map, check the map" on estimated cages; sheet photo thumbnail + "Click to zoom"; on Cartons cages "Cage postcodes <range> EST".
- **Check picture**: when the cage has a sheet photo, the main button reads "Check picture" (opens the viewer) and becomes Done once the viewer closes (✕ swaps it directly; the dialog close event covers Esc/Back, Chrome fires it ~0.5s late). Two-cage suburbs open the first cage's photo. No photo = Done straight away.
- **Map postcodes box** (`openEstimate`, `#dlg-est`): tap EST on a result, or "Map postcodes" in an opened Cartons panel. Shows compact runs (`compactCodes`) and each postcode with its suburbs: grey = not on this cage on this device, * = on the map's line. EST is a plain span (not tappable) inside other buttons (search rows, note lines) to avoid nested buttons.
- **Look-alike warning** (`similarPlaces` in js/match.js): the result lists names 1 letter off (2 when both are 6+ letters) that go to a different cage, e.g. Enfield LOCAL vs Penfield North Cartons. Worked out live. Same-destination pairs and short names skipped on purpose. Each is a button opening its own result.
- **Approved by**: adding or moving a suburb into a cage where it isn't on the sheets needs a name (add/move dialog `add-approver`, Edit-mode add line; never pre-filled). Stored in `data.approvals` (`suburb|cage` -> { by, at: YYYY-MM-DD }), moved on rename, removed with the suburb/cage and by applyUnsure, filtered in replaceData, exported. "On the sheets" = data/cages.json minus unsure.json (`ref.sheet`, `onSheet` in app.js). A renamed cage keeps `cage.sheetName` (its first name; no other cage may take it); `linkSheetNames` (in migrate) links cages renamed before this existed to the unclaimed sheet cage sharing over half their suburbs. Result and note show "Not on the sheets · approved by X, date", or amber "no approval noted" for older adds. Edit mode refuses clearing an off-sheet approver. If cages.json fails to load nothing is flagged (deliberate).
- **Sheet photos** (js/photos.js): one photo per cage, **on the device only** in IndexedDB (`cage-notes-photos`, key = normalised cage name), shrunk to 2000px JPEG. 📷 on each cage line in Edit mode; panel has View / Change / Remove. Rename moves the photo, delete removes it. Export/Import doesn't carry photos. Startup never waits on IndexedDB (some iOS versions stall).
- **Street map** (js/map.js, `#dlg-map`): Leaflet 1.9.4 (vendored in lib/leaflet, loaded on first open) + OpenStreetMap tiles (online) or the downloaded offline map (v28, see below), full-screen dialog. Opens from **Map** next to Edit on the main screen or `⋯ → Map` (whole city), **Show on map** in an opened Cartons panel (between View photo and Map postcodes; fits the cage's loop) and on Cartons result bands (pins the suburb, falls back to the cage). `app.openMap({ suburb, cage })`. Search box: prefix, word-start, contains, then editDistance <= 2 over data/suburb-points.json; pick = pin (circleMarker, no marker images shipped) at zoom 14. **Cage lines** control (every view): off = only the opened cage's dashed loop, on = all 6 cages' lines in cage colours + key with ±km (`within`; a cage with two maps shows both, e.g. South "±0.3/1.1 km"). `loops` maps cage -> `{ parts, within: [] }`, one part per region map; the – / Key button folds the key away and keeps the lines; state kept while the app is open. Lines are matched by cage name and use the live cage colour; a renamed or new cage has no line. Close has autofocus so the phone keyboard stays down. **Line sets** (v27, js/lines.js, localStorage `cage-lines`, separate from cage data so Reset never touches them): "Lines: <name> ▾" panel bottom-left switches between Built-in (the shipped loops, read-only, id 'builtin') and drawn sets, New/Rename/Delete via in-app `#dlg-lines` (no confirm()), Compare with another set (thin dashed). Edit lines (on Built-in it first asks to name a copy; copies are simplified at SIMPLIFY_M = 50 m) = edit toolbar: cage select, drag vertex, tap/drag midpoint to insert, New loop (tap map, tap first point to close), Remove point (3-point floor), Delete loop, Undo (cap 50; pops in-progress points while drawing), Done; every change autosaves; a drag under 10px is a tap (select); double-click zoom off while editing; handles hidden while drawing a new loop. Drawn sets are keyed by cage name; Manage rename calls `renameCageInSets`. ±km key only for Built-in. Export adds `lineSets`; Import `mergeSets` (fresh ids, "Pete (2)" on clash, skips exact duplicates, CAPS on counts). Not done (review nice-to-haves): Back on Firefox Android may jump to search, tile eviction is oldest-first. **Offline map** (v28, js/offline-map.js): `map/adelaide-20261028.pmtiles` (Protomaps vector extract, OSM data, maxzoom 14, 17.5 MB, bbox 138.158,-35.636,139.143,-34.248; made with the pmtiles CLI) is downloaded only on tap (map top-left box or `⋯ → Download offline map`), streamed into its own Cache API cache `cage-map` from the page (not in sw FILES, never deleted by activate; other entries deleted after a successful download; `navigator.storage.persist()` after). Read whole as a Blob into `pmtiles.FileSource` (no range requests) and drawn by protomaps-leaflet (lib/pmtiles, lib/protomaps-leaflet, loaded lazily), flavor light. The style has no metro suburb names, so map.js draws its own from suburb-points.json (divIcons in a `labels` pane, z450, zoom >= 11; `placeLabels()` on zoomend drops any name whose estimated box overlaps one already placed, in suburb-points order; Adelaide skipped as the style labels it). Online | Offline switch (localStorage `cage-map-base`, default online) shows once the vector map is built; online falls back to offline when `navigator.onLine` is false or after 3 OSM tile errors in one open ("No connection, showing offline map"). Downloads are single-flight with listeners (`onMapDownload`), so the map and menu both see progress; failure reasons offline/server/storage have their own messages. A corrupt file (`getHeader()` throws) shows "Offline map couldn't load" + Download again. Refreshing the extract = new file name in MAP_FILE (adds ~17.5 MB to git history each time).

## Data
- Each device keeps its own copy in localStorage; edits don't sync. Export/Import in `⋯` moves them. A sheetVersion bump only reaches a device via ⋯ → Reset to sheet data, which wipes on-device edits (Export first).
- **data/cages.json** (`sheetVersion` at the top): 19 sheet cages, 407 suburbs transcribed from the sheet photos (verified 2026-10-22, don't re-verify), now 406: Pinkerton Plains taken off Barossa (sheetVersion 3) because Pete confirmed 2026-10-27 it goes to Kadina, plus 6 Cartons cages (City, North, North East, Port, Regency, South; 308 suburbs, South's 37 west-map ones added v26) estimated from the region-map photos, unverified. Adding Cartons suburbs this way needs no sheetVersion bump (a bump nags phones to Reset): add them to cages.json, take them off adelaide-suburbs.json, add shipped postcodes, and list them in a new unsure.json `restore` step.
- **data/adelaide-suburbs.json**: 121 Adelaide metro suburbs (SA Gov list, 5000-5199, minus ones on a sheet). These show as LOCAL. Happy Valley is in both on purpose (Mildura's is a different place).
- **data/postcodes.json** (shipped reference, no reset needed): 643 sheet names matching exactly one locality in the SA Gov suburbs data (data.sa.gov.au, CC-BY 4.0, 2022-03-17), cross-checked against two more datasets (see HISTORY.md), plus (v26) the 37 suburbs that joined South Cartons, with their Local-list SA Gov postcode. Lyric's rule: **only add a postcode when 100% sure.** Left out on purpose: every Mildura-sheet name (interstate), Hamilton on Mount Gambier (Hamilton VIC), the 55 names with no SA match, and 9 doubtful ones Lyric is checking at work. Lyric fills gaps in-app.
- **Postcode precedence** (`postcodesAt` in app.js), per result band: a postcode typed in-app wins (`data.postcodes["suburbKey|cageKey"]` or `"suburbKey|local"`; '' means none; moved on cage rename, removed with the suburb or cage, imports keep only valid entries); else LOCAL bands use the Local list's postcode and cage bands use data/postcodes.json. Per band because Happy Valley LOCAL (5159) and Happy Valley on the Mildura sheet are different places.
- **data/unsure.json** (shipped, no reset): Cartons suburbs not 100% sure, per cage, with a `version`. `applyUnsure` (js/store.js) moves each one still on that cage to Local (shipped postcode if exactly one; a typed "suburb|cage" postcode moves to "suburb|local") and sets `data.unsureApplied`. Runs on start and after Import/Reset; replaceData copies `unsureApplied`, so old exports get the move and new exports keep Lyric's moves. Data with `unsureApplied` 0 (sheet defaults, old exports, Reset) gets the current list, then every `restore` step (so old exports also get suburbs added to cages.json later, e.g. v26 South). Data that applied an older version only runs the newer `restore` steps (`restore: { "<version>": { cage: [names] } }`, `restoreSure`): each listed suburb still in Local and on no cage goes back to its cage (a typed Local postcode goes with it); nothing is re-hidden, so Lyric's in-app moves stay. To un-hide some for everyone: delete them from `cages`, list them under a new `restore` step with the next version, and bump `version`. Never add names to the list expecting phones to hide them; that only reaches fresh data. Lyric moves the rest back in-app as he checks them. Currently (v3) 189 sure, 119 unsure (v3 = the 37 South west-map suburbs); Regency has 3 suburbs (Angle Park, Kilburn, Regency Park).
- **data/estimated.json** (shipped, no reset): `cages` = the estimated cages (remove one once Lyric verifies it). `areas` = per Cartons cage, every postcode inside its region map's drawn loop with suburbs `{ name, edge? }`; the ranges on the note, result and panel come from here (`mapArea`/`postcodeRange` in app.js), not the live suburbs. Ranges: City 5000-5082, North 5106-5121, North East 5070-5098, Port 5011-5023, Regency 5010-5094, South 5022-5048 + 5160-5173 (two maps). `postcodeRange` splits where codes jump by over 100 and joins with ", " (Regency's 71 gap stays one range); the note line wraps a split range after the comma (`rangeTag` in js/manage.js). Edit the JSON by hand to change one; the scan scripts aren't in the repo. A Cartons cage renamed in-app loses its EST and map range (both keyed by name).
- **data/suburb-points.json** (shipped): `[name, postcode, lat, lng]` for 465 metro suburbs (SA Gov Suburbs_geojson, CC BY 3.0 AU, postcodes 5000-5199): centroid of the largest part, moved inside when it fell outside (Woodville, Hewett). Every Cartons and Local name has a point (tests.html checks).
- **data/region-loops.json** (shipped): the traced Cartons loops as lat/lng, one entry per region map (South Cartons has two entries), from the photo pixels via an affine fit to the suburb labels printed on each photo. `within` = worst label miss rounded up (km). Regency (v23) was refitted to 7 road intersections read off OSM tiles, using a second full photo (ShareX 2026-10-27_22-48-53): fit 0.08 km, leave-one-out worst 0.18 km, shown as ±0.3. v24: City, North, North East and Port refitted by matching the SA Gov state road network (data.sa.gov.au StateMaintainedRoads) to the orange roads on each photo (homography, robust chamfer fit), and City/North/NE snapped onto the drawn marker; ± = line movement over refits on random halves of the roads plus tracing: City 0.3, Port 0.4, NE 0.4, North 0.6. South couldn't be road-fitted (only 2-3 parallel highways on its map) and keeps the label fit (±1.1). v26: South's second (west) map, ShareX 2026-10-28_22-43-16, road-matched the same way: labels 0.14 km RMS, half-fits within 0.13 km, shown ±0.3. Derived from work photos, Lyric OK'd it public 2026-10-27. Traced pixel data (maps.json) is in an old session scratchpad, not the repo.
- **Renamed default cages**: `CAGE_RENAMES` in js/store.js, applied once per device by `applyRenames` (`data.renamesApplied`, copied by replaceData) via `app.migrate()` on start and after Import/Reset; only renames a cage still called the old name. The photo follows via `movePhotosOfRenamedCages` (app.js), retried each start. To rename another default: change data/cages.json (no sheetVersion bump), add a CAGE_RENAMES entry with the next id, and update tests.html and the RENAMED map in tests-ui.html.
- **Lyric's placement rules**: suburbs on the printed sheets stay on their sheet cage even where a region map overlaps (e.g. Aldinga/Seaford/Willunga stay Victor Harbor); he moves things himself in-app. Suburbs still LOCAL weren't inside any region map.
